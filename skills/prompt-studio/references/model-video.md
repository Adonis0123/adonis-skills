# Model Video

A video model generates the frames. Realistic, not exactly controllable, billed per second. Rules below were checked on 2026-10-27; models change fast, so re-check a model's official page when a run behaves unexpectedly and mark unchecked details `UNVERIFIED`.

## Before every run

This is a hard cost gate: state channel, model, duration, resolution, number of clips and estimated cost, and wait for a yes. Run exactly one short low-resolution preview before the final, and ask again before the final run. Ambiguous 动效 / 动起来 requests do not come here: SKILL.md routes them to Code Video unless the user wants realistic motion or names a video model.

## Prompt structure (shared by all models)

1. Subject → action → setting → camera → light and style → sound/dialogue. Duration, aspect ratio and resolution are parameters, not prose.
2. One camera move and one main action per shot. Write motion as from-to ("walks from the doorway to the window, stops, turns"); a bare verb makes the subject wobble in place.
3. Repeat fixed traits (outfit, colours, 3–5 hex values) in every clip of a sequence.
4. Describe what should be there instead of listing what should not.
5. Image-to-video: the image fixes the first frame; the prompt only adds what the image lacks — motion, camera, sound. Do not re-describe the picture.

## Image to video, and sequences

1. Make the first frame with an image Channel first; when several characters or props share a shot, compose them into one image rather than pasting cut-outs (pasted cut-outs animate like stickers). Keep passing each character's reference sheet.
2. A subject crossing the frame: first frame at the start position, last frame at the end. Same image as first and last frame gives a seamless loop. Look at a staged last frame before spending on the video: an edit that moves the subject often moves other things too, and the video then animates that drift.
   A busy first frame (many props, tiles or fine detail) warps and duplicates elements when animated. Stage a simpler frame, or keep everything but one subject still and say so explicitly.
3. Continuous shots: take the real last frame of the previous clip as the next first frame — `ffmpeg -sseof -0.05 -i shot1.mp4 -frames:v 1 last.png`. New camera angle: make a new first frame, same references.
4. Keep resolution and fps identical, then join without re-encoding: `ffmpeg -f concat -safe 0 -i list.txt -c copy out.mp4`.

## Quality gate

1. `ffprobe` the file: duration, resolution and fps as briefed.
2. Extract one frame per second (`ffmpeg -i out.mp4 -vf fps=1 frames/%03d.png`) and look: identity drift, warped hands or faces, text artefacts, the motion actually happening.
3. On a moderation block: stop, tell the user, offer a different direction. Do not paraphrase to evade the filter.
