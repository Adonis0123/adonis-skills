# Research brief

One file, given unchanged to every researcher. Every field is required; write `none` rather than deleting a field.

```markdown
# <question in one line>

## Role and rules

You are an independent <designer / engineer / analyst>. Others answer this same brief separately. A finding is used when two of you share it, or when one of you backs it with first-hand evidence the coordinator can check (a source URL, a reproduction), so give your own judgment with evidence. Read-only: do not edit any repository file.

## Context

The product, its users, and the rule the result must serve (for example "beginners never have to stop and think"). Repository path and the files worth reading.

## Inputs

Screenshots, logs or data, each with a path and what it shows. (The coordinator has looked at every one.)

## Questions

Numbered. Each asks for one recommendation, the alternatives rejected and why, and a confidence (high / medium / low).

## Evidence

At least N real sources with URLs (for design: GitHub projects of the same kind and well-known products). Mark anything not verified UNVERIFIED.

## Output

Language, format, word limit, ranking (P0 / P1 / P2 with effort S / M / L), and what is out of scope (for example new backend features).
```

Keep the brief free of the coordinator's own conclusions; they would make the answers agree for the wrong reason.
