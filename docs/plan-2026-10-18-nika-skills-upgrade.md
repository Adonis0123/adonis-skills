# Nika Skills: Brand, Visitor Experience, and Architecture Upgrade

**Status:** Approved design; not implemented
**Date:** 2026-10-18
**Branch:** `feat/nika-skills-upgrade`
**Brand source:** the private `adonis-brand` repo (`$BRAND_REPO`, default `../adonis-brand`) (asset repo, no importable package)
**Live site:** https://adonis-skills.vercel.app/

## Background

Four research passes on 2026-10-17 (code architecture, live visitor walkthrough, peer catalog sites, brand repo) found:

- **Visitors cannot find, judge, or install well.** Search matches whole phrases only ("code review" and "代码审查" return nothing). Only `npx skills add` is shown; Claude Code plugin and Hermes installs are missing. Cards show the model-facing `description`. Skill docs sit in a 60vh nested scroll box. Italics do not render. Primary button contrast is about 2.2:1. The search box has no visible focus. Cards nest `<button>` in `<a>`. `/zh` still renders `<html lang="en">`. Site-level 404 is the unstyled Next.js default. On mobile, the first screen shows no search and no skill.
- **Design contract and tokens disagree.** `docs/web-ui-clay-contract.md` specifies warm peach and forbids bottom outer lines; `apps/web/src/styles/shadcn-theme.css` sets `--clay-peach: #93abd7` (blue) and uses `0 3px 0` in `--clay-shadow-card`.
- **Loose data contract.** The generator, hand-written TS types in `apps/web/src/lib/skills.ts`, and committed JSON can drift. CI runs no vitest and no `scripts/__tests__`.
- **SEO is title-only.** No `metadataBase`, OpenGraph, hreflang, canonical, sitemap, robots, or OG image.
- **Brand mismatch.** The brand repo decided on 2026-10-18 (commit `4340586`) that Nika is the only public name and `Adonis0123` is only a GitHub ID. The current logo is a clay PNG letter "A"; brand rules require flat fills with an ink outline for logos and icons. The brand assigns one jelly character per project; Kiki (琪琪) is registered for "Skills".

Terminology follows `CONTEXT.md` (Catalog Site, Visitor, Host).

## Goals

1. A Visitor can find a skill by English or Chinese keywords, judge it from a human-written summary, and install it for their Host in one copy.
2. The Catalog Site presents as **Nika Skills**, consistent with the Nika personal brand.
3. Components never reference raw color values; swapping brand values touches only the brand token layer.
4. One typed schema governs generated data; CI catches drift and runs existing tests.
5. The site is discoverable by search engines and readable by LLMs.

## Scope

In scope:

- Brand tokens, logo, favicon, OG image, hero illustration, and a rewritten visual contract.
- Data schema and new frontmatter fields.
- Nine Visitor-facing features (Phase 3).
- SEO and LLM entry points.
- CI test coverage.
- Brand repo registration (`adonis-brand`).

Out of scope:

- Install counts (no data source), favorites, compare, version history.
- Translating SKILL.md bodies.
- Changing URLs, skill slugs, `npx skills add adonis0123/adonis-skills`, or the plugin marketplace name.

## Phases

### Phase 1: Brand foundation

- Three-layer tokens in `apps/web/src/styles/`; remove the `antd` layer residue and the forbidden `0 3px 0` shadows.
- Rewrite `docs/web-ui-clay-contract.md` to D3, D11, D12.
- Logo lockups (D9), favicon, apple-icon; hero options via Grok Build (D10).
- Rename display name to Nika Skills (D7); attribution per D6.
- Brand repo registration (D8).

### Phase 2: Data contract

- Shared zod schema for lite and detail indexes; generator validates against it; `apps/web/src/lib/skills.ts` derives types from it.
- Catalog file (D14) and tag vocabulary (D16) with validation errors that name the slug, field, and fix.
- agy drafted summaries, `summary_zh`, use cases, and tag assignments for 29 skills; facts spot-checked against each SKILL.md before applying.
- CI additions (D20).

### Phase 3: Visitor features

1. Tokenized and fuzzy search covering Chinese trigger words; query in the URL.
2. Host install tabs (Claude Code plugin, `npx skills`, Hermes) driven by one hosts config; last choice remembered.

4. Full-page doc reading with a table of contents; standard markdown renderer.
5. Tag filter and Host badges.
6. Accessibility: contrast, visible focus, no `<button>` inside `<a>`, distinct copy-button names, correct `html lang`; styled site-wide 404.

## Risks

- **`html lang` fix requires layout restructuring.** The root layout sits outside `[lang]`; moving `<html>` into `[lang]/layout.tsx` touches the proxy and not-found routing. Mitigation: verify every route, including the site 404, after the move.
- **Generated image quality.** Grok output may drift from the character sheet. Mitigation: reference images attached, user picks; fall back to a flat SVG hero.
- **Copy accuracy.** agy may describe capabilities a skill lacks. Mitigation: each summary checked against its SKILL.md.
- **Shantell Sans licensing and offline loading.** Mitigation: confirm OFL license and self-host via fontsource, matching the existing offline-font CI check.

## Acceptance Criteria

Each phase:

- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm build`, vitest, and `scripts/__tests__` pass.
- [ ] agent-browser walkthrough of three Visitor paths (first visit, find a capability, install) at 1440 and 390 widths, light and dark, en and zh, with screenshots.
- [ ] Codex review findings verified and resolved or explicitly deferred.

Overall:

- [ ] "code review" and "代码审查" each return relevant skills.
- [ ] Every detail page shows install commands for all three Hosts with working copy.
- [ ] `grep` finds no raw hex values in `apps/web/src/components/**`.
- [ ] Changing a brand token value requires no component edits; adding a Host requires only the hosts config.
- [ ] Primary text and buttons meet WCAG AA 4.5:1 (measured).
- [ ] `/zh/*` renders `<html lang="zh">`.
- [ ] CI fails with a fix hint when generated JSON is stale.
- [ ] `sitemap.xml`, `robots.txt`, `llms.txt`, `/skills/<slug>.md`, and OG images resolve on a preview deploy.
- [ ] `adonis-brand` lists the site under Kiki and has `projects/skills/BRAND.md`.
